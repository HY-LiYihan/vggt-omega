# VGGT-Omega TCP 推理服务调用教程

本文档介绍如何启动和调用本地部署的 VGGT-Omega 多视图重建 TCP 服务。服务输入**多张图片**或**一整段视频**，单次前向即可输出每帧的相机位姿（外参/内参）与密集深度图。

## 1. 概述

| 项目 | 说明 |
|---|---|
| 模型 | VGGT-Omega-1B（`vggt_omega_1b_512.pt`，4.6GB，Meta/Oxford CVPR 2026 Oral） |
| 服务形态 | 裸 TCP 长连接 + 自定义帧协议（与 MoGe 服务一致） |
| 默认端口 | **8317**（`--port` 可改；若与 MoGe 服务同跑请错开端口） |
| 输入模式 | `images`：1~64 张 jpg/png；`video`：一整段 mp4，服务端均匀采样 1~64 帧 |
| 输出 | `depth (N,H,W)`、`depth_conf (N,H,W)`、`extrinsics (N,3,4)`、`intrinsics (N,3,3)` |
| 硬件需求 | 单次推理约 6GB 显存（8 帧 @ 512 分辨率实测）；模型常驻 4.3GB |

## 3. 协议

### 3.1 帧格式

所有消息（JSON 头、二进制负载、响应）均按 **4 字节小端 uint32 长度前缀 + 载荷** 封帧。

### 3.2 请求（单次推理 = 1 个 JSON 头帧 + 1 个二进制帧）

```json
{
  "type": "infer",
  "model": "vggt",               // 可选: "vggt"(默认) | "sam3"(SAM3 分割, 见第 9 章)
  "mode": "images",              // "images" | "video"
  "images_bytes": [18324, 17502],  // images 模式: 各张图片字节数
  "video_bytes": 6539814,          // video 模式: 视频总字节数
  "params": {
    "resolution": 512,             // image_resolution, 须为 16 的倍数
    "preprocess": "balanced",      // balanced | max_size
    "num_frames": 8                // video 模式采样帧数
  }
}
```

> 统一服务（`d:\MoGe3\serve.py`，见 2.3）在同一端口同时提供 VGGT 与 SAM3，
> 用请求头 `model` 字段区分；**不带 `model` 字段默认 vggt，旧客户端无需改动**。

JSON 头帧之后紧跟二进制帧：`images` 模式为各张图片字节**顺序拼接**；`video` 模式为完整视频文件字节。二进制上限 512MB。

### 3.3 响应序列（同一连接按序到达）

```
{"type":"status","stage":"received","payload_bytes":...}
{"type":"status","stage":"inferring","frames":N}
{"type":"array","name":"depth","shape":[N,H,W],"dtype":"float32"}   + 数组原始字节(小端 f32)
{"type":"array","name":"depth_conf","shape":[N,H,W],...}           + 字节
{"type":"array","name":"extrinsics","shape":[N,3,4],...}            + 字节
{"type":"array","name":"intrinsics","shape":[N,3,3],...}           + 字节
{"type":"done","frames":N,"height":H,"width":W,"fov_x_deg":...,"fov_y_deg":...,
 "decode_ms":...,"infer_ms":...,"total_ms":...}
```

- `extrinsics[i]` = `[R|t]` (3×4)，世界系到相机系；相机中心 = `-R^T · t`
- `intrinsics[i]` = 3×3 相机内参（fx, fy, cx, cy）
- `depth_conf` 越大越可信（通常 > 5 为高置信）

### 3.4 错误处理

任何参数/解码错误返回 `{"type":"error","stage":"request","message":"..."}`，**连接不断开**，可继续发下一次请求。非法 JSON 同样返回 error。服务端支持长连接连续推理。

## 4. 最小客户端（Python）

```python
import json, socket, struct
import numpy as np

def recv_exact(s, n):
    buf = b""
    while len(buf) < n:
        c = s.recv(n - len(buf))
        if not c: raise ConnectionError("closed")
        buf += c
    return buf

def infer(host, port, images, params=None):
    """images: jpg/png 字节列表; 返回 (arrays dict, done dict)"""
    params = params or {"resolution": 512}
    header = {"type": "infer", "mode": "images",
              "images_bytes": [len(b) for b in images], "params": params}
    with socket.create_connection((host, port), timeout=120) as s:
        s.settimeout(120)
        for data in (json.dumps(header).encode(), b"".join(images)):
            s.sendall(struct.pack("<I", len(data)) + data)
        arrays, done = {}, None
        while True:
            m = json.loads(recv_exact(s, struct.unpack("<I", recv_exact(s, 4))[0]))
            if m["type"] == "array":
                n = int(np.prod(m["shape"]))
                arrays[m["name"]] = np.frombuffer(
                    recv_exact(s, n * 4), dtype="<f4").reshape(m["shape"])
            elif m["type"] == "done":
                return arrays, m
            elif m["type"] == "error":
                raise RuntimeError(m["message"])

arrays, done = infer("127.0.0.1", 8317, [open("view1.jpg", "rb").read(),
                                          open("view2.jpg", "rb").read()])
print(done["frames"], "帧, 深度范围:", arrays["depth"].min(), "~", arrays["depth"].max())
```

视频模式只需把 header 换成 `{"type":"infer","mode":"video","video_bytes":len(video), "params":{"num_frames":8, "resolution":512}}` 并发送整个视频字节，服务端自行采样。

## 5. 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| `resolution` | 512 | 输入缩放目标。512 为推荐值；须为 16 的倍数。越大越准也越慢 |
| `preprocess` | balanced | `balanced`：token 数 ≈ resolution²（宽高比自动适配）；`max_size`：长边 = resolution |
| `num_frames` | 8 | 仅 video 模式：均匀采样帧数。1~64 |

## 6. 并发行为

- 多个连接可同时请求，**GPU 前向由全局锁串行执行**（排队等待，互不影响结果）
- 图片/视频解码在线程池并行进行，不阻塞事件循环
- 排队延迟 ≈ (前面请求数) × 各自前向耗时；单请求前向时间随帧数近似线性增长

## 7. 实测性能（RTX 4080 Laptop 12GB, fp32）

| 场景 | 前向耗时 | 显存峰值 |
|---|---|---|
| 4 帧 @ 384×688 (balanced 512) | 1.9 s | ~5.6 GB |
| 8 帧 @ 384×688 | 1.2~2.5 s | ~5.6 GB |
| 16 帧 @ 384×688 | 3.3 s | ~5.9 GB |
| 单图 | ~1.4 s | ~5.0 GB |

视频模式额外含服务端解码采样耗时（6.5MB mp4 采 8 帧约 1.9s）。客户端全程耗时 = 传输 + 解码 + 前向，典型 3s 左右。

### 7.1 帧数与分辨率极限（1080p 视频实测，12GB 显存）

> 显存打满后 Windows WDDM 会把 GPU 显存换页到系统内存，前向耗时**百倍劣化**且推理不中断，表现为请求长时间无响应（需重启服务）。请勿超过下表"实用上限"。

| resolution | 输出分辨率 | 实用上限（流畅） | 勉强可用 | 不可用 |
|---|---|---|---|---|
| 512（默认） | 688×384 | **32 帧**（前向 6.6s） | 48 帧（52.9s） | 64 帧（服务上限，换页卡死） |
| 1088 | 1456×816 | **4 帧**（前向 2.6s） | 8 帧（30.0s） | 12 帧 |

- 显存峰值随帧数近似线性增长：512@32帧 ≈ 11.1GB、1088@4帧 ≈ 10.3GB（同机含其他进程占用）
- 若 GPU 上有浏览器/游戏等其他占用，上限相应降低；独占 GPU 时可适当上浮

# SAM3 分割 TCP 服务调用教程（统一端口 8317）

基于 Ultralytics（`ultralytics==8.4.160+`）封装的 SAM3 分割服务，支持两种模式：

| 模式 | 输入 | 输出 | 底层 |
|---|---|---|---|
| `text` | 一张图 + 名词短语列表 | 所有匹配实例的 mask/框/分数 | `SAM3SemanticPredictor`（开放词汇概念分割） |
| `reference` | 参考图 + 参考图上的二值 mask + 目标图序列 | 目标图上同物体的 mask | `SAM3VideoPredictor`（视频跟踪传播） |

**典型组合用法**：第 1 帧用 `text` 模式切出目标物体 mask，后续帧用 `reference` 模式传播跟踪（比每帧都跑文本提示更快更稳）。

> **接入方式**：SAM3 已并入**统一服务**（`d:\MoGe3\serve.py`，与 VGGT 共用 8317 端口），
> 请求头带 `"model": "sam3"` 即路由到 SAM3；不带 `model` 字段默认走 VGGT，旧客户端不受影响。
> 若只需 SAM3 独立部署，也可单独运行 `sam3/serve.py`（见 9.3 备选）。

## 10. 协议

帧格式与 VGGT 服务完全一致（4 字节小端长度 + payload）。统一服务地址 `127.0.0.1:8317`，
请求头须带 `"model": "sam3"`。

### 10.1 text 模式

请求 = JSON 头帧 + 图片二进制帧：

```json
{"type": "infer", "model": "sam3", "mode": "text", "image_bytes": 123456,
 "text": ["red car", "person wearing a hat"], "conf": 0.25}
```

- `text`：名词短语列表（开放词汇，可写描述性短语如 `"person with red cloth"`）
- `conf`：可选，实例置信度阈值，默认 0.25

响应序列：`status(received)` → `status(inferring)` → 3 个数组 → `done`

| 数组 | shape | 说明 |
|---|---|---|
| `masks` | (K, H, W) uint8 | 每个实例的全分辨率二值 mask（0/1） |
| `boxes` | (K, 4) float32 | 每实例 xyxy 像素坐标 |
| `scores` | (K,) float32 | 每实例置信度 |

`done` 消息含：`k`（实例数）、`prompts`、`height/width`、`conf_thresh`、`infer_ms`。
无匹配时 K=0，数组仍照常发送。

### 10.2 reference 模式

请求 = JSON 头帧 + 二进制帧（**参考图 || 参考 mask PNG || 目标图...** 拼接）：

```json
{"type": "infer", "model": "sam3", "mode": "reference",
 "ref_image_bytes": 111111, "ref_mask_bytes": 2222,
 "images_bytes": [33333, 44444]}
```

- 参考图与参考 mask（PNG，灰度 >127 视为目标）分辨率必须一致
- 目标图 1~32 张，分辨率须与参考图一致（视频跟踪的硬性要求）
- mask 服务端自动转外接框提示帧 0，由跟踪器解出精确 mask 后向后续帧传播

响应序列：`status` × 2 → 数组 → `done`

| 数组 | shape | 说明 |
|---|---|---|
| `masks` | (N, H, W) uint8 | 每张目标图上跟踪到的物体 mask |

`done` 含：`frames`（=N）、`height/width`、`scores`（每帧跟踪得分）、`mask_areas`、`infer_ms`。

## 11. 最小客户端（Python）

```python
import json, socket, struct
import numpy as np

def send_msg(s, payload):
    s.sendall(struct.pack("<I", len(payload)) + payload)

def recv_msg(s):
    hdr = b""
    while len(hdr) < 4:
        hdr += s.recv(4 - len(hdr))
    (n,) = struct.unpack("<I", hdr)
    data = b""
    while len(data) < n:
        data += s.recv(n - len(data))
    return data

def call_text(host, port, jpg: bytes, texts: list[str]):
    with socket.create_connection((host, port), timeout=60) as s:
        send_msg(s, json.dumps({"type": "infer", "model": "sam3", "mode": "text",
                                "image_bytes": len(jpg), "text": texts}).encode())
        send_msg(s, jpg)
        arrs, done = {}, None
        while True:
            msg = json.loads(recv_msg(s))
            if msg["type"] == "array":
                raw = recv_msg(s)
                arrs[msg["name"]] = np.frombuffer(raw, msg["dtype"]).reshape(msg["shape"])
            elif msg["type"] == "done":
                done = msg
                break
            elif msg["type"] == "error":
                raise RuntimeError(msg["message"])
        return arrs, done

masks, done = call_text("127.0.0.1", 8317, open("a.jpg", "rb").read(), ["red car"])
print(f"切出 {done['k']} 个实例, 分数 {masks['scores']}")
```

> 数组读取注意：SAM3 的数组帧头含 `bytes` 字段、数组字节是**独立的长度前缀帧**
> （如上 `recv_msg(s)`）；VGGT 的数组字节则**裸跟在 JSON 帧后**（无前缀，按 shape×dtype 长度读）。
> 两种格式兼容的通用客户端见 [test_unified_service.py](../../test_unified_service.py) 的 `rpc()`。

reference 模式客户端见 [sam3/test_service.py](../../sam3/test_service.py) 的 `call_reference()`。

## 13. 注意事项

1. **概念顺序**：`masks[i]` 对应 `text` 列表中第 i 个概念的实例（按概念分组拼接）
2. **跨图参考的本质**：Ultralytics 的参考模式通过视频跟踪实现，参考图与目标图应来自**同一视频/同一场景**（时序相近）；差异过大的两幅图会退化
3. **分辨率一致性**：reference 模式要求所有图同分辨率，服务端已做校验
4. **错误不断连**：坏图/参数错误返回 `{"type":"error","stage":"request|infer","message":...}`，连接保持可用
